## Clarifications

### Session 2025-10-17
- Q: 未命中任何类别时如何处理？ → A: 仅加标签 `Chrono/Uncategorized`，不改变收件箱状态（不归档、不已读）。
- Q: 日志是否包含被舍弃候选及分数？ → A: 仅记录最终类别与关键命中特征（不记录候选/分数）。
- Q: 低干扰清单是否默认标记已读？ → A: 默认不标记已读（可在设置中开启）。
- Q: 错误分类用户反馈如何处理？ → A: 不记录任何修正（仅视为用户个体行为），不做在线微调。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 自动识别并降噪「新闻资讯/营销」(Priority: P1)

当用户收到新闻资讯或营销类群发邮件时，系统自动打上清晰标签并降低对主收件箱的干扰（默认不跳过收件箱，支持可选标记已读）。

**Why this priority**: 这类邮件占比高且最影响收件箱噪声，优先解决可显著提升使用体验与信任度。

**Independent Test**: 选取包含与不包含列表标识的样本邮件，触发一次分类运行，验证是否正确打上「Newsletters/Promotions」标签并执行既定降噪策略。

**Acceptance Scenarios**:

1. Given 邮件具有明确的列表标识信号，When 收到邮件，Then 自动标记为「Newsletters」或「Promotions」并应用默认降噪策略。
2. Given 邮件缺少强列表信号但包含典型页脚措辞，When 收到邮件，Then 在不影响高优先邮件的前提下被正确识别并降噪。
3. Given 邮件属于重要场景（如安全、交易），When 同时含有少量列表措辞，Then 不应被错误降噪。

---

### User Story 2 - 保留并凸显「交易与安全」邮件 (Priority: P1)

当用户收到订单、物流、账单或安全相关邮件，系统自动标注对应场景标签，并默认保留在收件箱以便及时处理，同时提供到期后的自动归档策略。

**Why this priority**: 该类邮件时效性与重要性高，错误降噪代价大，必须稳定可靠。

**Independent Test**: 使用带有交易与安全特征的样本邮件，验证是否被正确分类到「Orders/Shipping/Bills/Security」，并在到期后按策略自动归档。

**Acceptance Scenarios**:

1. Given 邮件包含明确交易/物流语义，When 收到邮件，Then 被正确分类并保留在收件箱。
2. Given 邮件属于安全警报或验证码，When 收到邮件，Then 被正确分类并不被降噪或延迟处理。
3. Given 邮件超过到期时点，When 触发生命周期策略，Then 自动归档且不影响用户可见性与可追溯性。

---

### User Story 3 - 行程邮件的聚合与时点后处理 (Priority: P2)

当用户收到行程相关邮件（航班、酒店等），系统在行程前凸显可见性（可选加星），行程结束后自动清理归档。

**Why this priority**: 行程类邮件具有明确时间窗口，自动化可减少手动维护成本。

**Independent Test**: 投入含有出行日期的样本，验证在行程前展示策略与行程结束后的自动归档行为。

**Acceptance Scenarios**:

1. Given 邮件包含行程关键信息，When 收到邮件，Then 被正确归类并（可选）加星标。
2. Given 行程结束时间已过，When 到达+1日策略检查，Then 自动归档且不误伤仍在进行的行程。

---

### User Story 4 - 系统自动回复的静默处理 (Priority: P2)

当用户收到系统自动回复或退信通知时，系统自动将其归入系统类标签并降噪，不干扰主收件箱。

**Why this priority**: 避免收件箱循环通知与无效提醒，降低干扰。

**Independent Test**: 提供包含自动回复/退信样本，验证自动分类与降噪策略执行。

**Acceptance Scenarios**:

1. Given 邮件呈现典型系统自动回复特征，When 收到邮件，Then 自动降噪且不影响其他规则判定。
2. Given 用户需要追溯，When 通过标签查看，Then 可完整看到被静默处理的此类邮件。

---

### User Story 5 - 可解释的决策输出 (Priority: P3)

系统在每次分类时提供简要、用户可理解的解释说明（例如命中特征与优先级裁决），用于透明化与后续调优。

**Why this priority**: 解释性提升用户信任度，并便于后续持续改进。

**Independent Test**: 对任一样本邮件，检查分类结果是否包含命中特征列表与最终决策理由。

**Acceptance Scenarios**:

1. Given 一封被分类邮件，When 查看结果，Then 能看到分类标签、命中特征摘要与决策理由。
2. Given 决策存在多类候选，When 执行优先级裁决，Then 解释应体现裁决依据与被舍弃候选。

### Edge Cases

- 同时包含交易与营销信号时，应优先交易场景，且不触发降噪。
- 边界语言与多语种（中/英/德等）关键词差异应不影响高优先场景判定。
- 用户转发的交易类邮件不应被识别为群发类。
- 极端情况下的误杀防护：任何高优先场景不得被降噪。
- 缺失明显信号时，结果应保持保守，避免对收件箱产生负面影响。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001 分类范围与层级**：必须提供父级命名空间与二级场景标签结构（如 Finance/Security、Purchases/Orders、Updates/Newsletters 等），并确保分类结果唯一、互斥且可追溯。
- **FR-002 决策优先级**：必须遵循明确的优先级裁决顺序，以避免冲突与误杀：
  - P0 绝对排除优先（系统自动回复类）
  - P1 明确交易/行程结构化意图优先于其他信号
  - P2 交易意图优先于广播意图
  - P3 联系人/个人关系优先于通用内容
  - P4 群发列表标识优先于一般关键词
- **FR-003 降噪策略（低干扰清单）**：对新闻资讯与营销类邮件，默认不开启“跳过收件箱”，且默认不标记已读；用户可在设置中开启“跳过收件箱”或“标记已读”。
- **FR-004 高优先场景展示（高优先清单）**：对安全、订单、物流、账单、行程等高优先邮件，默认保留在收件箱并可配置到期自动归档；任何情况下不得被误降噪。
- **FR-005 生命周期策略**：支持针对不同场景的时间到期后处理策略（例如：订单30天、物流送达+3天、行程结束+1天、账单60天），并允许用户在设置中调整时长。
- **FR-006 决策可解释性**：每次分类需输出命中特征摘要与最终裁决依据，不记录候选列表或分数；如需深入排查，仅可在开发模式下短期开启候选输出。
- **FR-007 用户可控与回溯**：所有自动动作必须可撤销，通过标签视图能回溯全部归类记录；提供最小化的偏好设置用于关闭或调整降噪策略。
- **FR-008 MVP 范围**：首发覆盖全部14类（Finance/Security、Finance/Bills、Purchases/Orders、Purchases/Shipping、Travel/Flights、Travel/Hotels、Work/Tasks、Work/Calendar、Updates/Newsletters、Updates/Promotions、Updates/Legal、Personal/Important、System/Auto-Replies、Updates/Product）。
- **FR-009 个人重要联系人**：支持从联系人来源识别重要联系人并给予优先展示；同时提供“手动白名单”作为补充途径。
- **FR-010 未命中处理**：当无法判定到任何已定义类别时，必须仅打上 `Chrono/Uncategorized` 标签，不改变收件箱、已读或星标状态；用于覆盖率统计与后续调试。
- **FR-011 日志粒度策略**：默认仅记录最终类别、关键命中特征与动作策略摘要；不记录候选类别与分数，以控制日志体积与性能影响。
- **FR-012 用户修正与在线微调**：不记录用户的标签移动等修正事件；不进行自动或离线权重更新与在线微调；后续是否引入由后续版本评估。

### Key Entities *(include if feature involves data)*

- **Category（类别）**：二级标签的业务含义与边界定义（如 Finance/Bills、Updates/Promotions）。
- **Signal（信号）**：用于判定类别的外在特征集合（如群发标识、主题/内容线索、关系与上下文）。
- **Candidate & Decision（候选与裁决）**：候选类别集合与最终唯一裁决结果及其解释性信息。
- **Action Policy（动作策略）**：与类别绑定的默认处理策略（保留、降噪、到期归档等）。
- **Preference（偏好）**：用户可调整的策略参数（如是否跳过收件箱、到期时长）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001 覆盖率**：≥ 90% 的样本邮件被自动归入明确的类别（不含明确排除类）。
- **SC-002 准确率**：被分类样本中 ≥ 95% 的结果与人工“黄金标准”一致。
- **SC-003 关键误杀为零**：高优先场景被错误降噪（如被归入低干扰清单）的比例为 0%。
- **SC-004 用户体验**：在一次批量运行中，典型用户等待时间不超过 5 秒（100 封样本级别），单封邮件的可感知延迟接近即时。
- **SC-005 透明与可控**：≥ 95% 的被分类邮件提供可读解释摘要；≥ 90% 的用户在首周无需调整默认策略。
- **SC-006 设置稳定性**：首月内用户更改默认设置（降噪/生命周期策略）的比例 ≤ 15%。
